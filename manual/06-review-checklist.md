# 06. 리뷰 체크리스트 (Jev 통합 PR · 케이스 문서)

> 앞 문서들의 요약본이다. 항목마다 근거 문서를 링크한다. 확인일: 2026-09-24

## 적용 판단 ([01](01-fit-assessment.md))
- [ ] 코드로 정확히 풀 수 있는 부분(규칙, 계산, 날짜, 카운팅)을 Jev에 맡기지 않았다
- [ ] 출력이 닫힌 선택지, yes/no, 서술 가능한 등급 중 하나다 (생성 작업이 아니다)
- [ ] 틀렸을 때의 경로(임계값, 사람, fallback)가 있다

## 질문 ([02](02-question-design.md))
- [ ] 질문과 임계값이 **한 모듈**에 있고, 사람이 그 파일만 보고 리뷰할 수 있다
- [ ] 질문 하나에 판단 하나. "and"/"or"로 묶인 조건이 없다
- [ ] instructions만으로 의미가 완전하다 (ID에 의존하지 않는다). Noul은 높은 값이 yes다
- [ ] Choice에 `other`/`none`이 있다 (목록이 모든 입력을 덮는 게 확실한 경우는 예외)
- [ ] Score 레벨은 2~10개의 서술문이고, null이나 숫자만 쓴 레벨이 없다
- [ ] 같은 state의 질문이 **한 요청**에 모여 있다. 두 번째 요청에는 의존성 사유가 적혀 있다
- [ ] 여러 항목을 한 state에 몰아넣고 순위를 매기게 하지 않는다
- [ ] state에 질문과 무관한 큰 덩어리가 없다

## 코드 ([03](03-integration.md))
- [ ] 모델 **버전 ID를 고정**했다 (`jev-latest` 금지. 실험 코드는 예외)
- [ ] 401/403(키), 400/422(형식), HTML 403(WAF), 429/5xx, 타임아웃을 처리하고, 모두 **fallback으로** 이어진다
- [ ] 실시간 경로에 지연 상한(총 재시도 예산이나 AbortSignal)이 있다
- [ ] 빈 state를 코드에서 막는다
- [ ] 임계값이 어떤 값을 읽는지(confidence / p_top / noul / score) 주석에 적혀 있다
- [ ] API 키가 서버에만 있다. 로그에 body(PII)를 남기지 않는다

## 평가 ([04](04-evaluation.md))
- [ ] 평가셋(튜닝과 테스트 분리)이 있고, 임계값의 근거가 문서화되어 있다
- [ ] 한국어 입력이 있으면 한국어 슬라이스를 따로 평가했다 (번역 쌍이 아니라 원문 한국어 케이스)
- [ ] 임계값 근처(± 0.07)에 여유 구간을 두었고, 평가를 두 번 이상 돌려 결정이 뒤집히는 표본을 확인했다
- [ ] 결정 gold가 질문별 라벨과 별도로 있고, 정책에서 유도하지 않았다 ([templates/evalset.md](../templates/evalset.md))
- [ ] 정책 단위 테스트가 녹화한 응답으로 분기 경계를 검증한다
- [ ] confidence 임계값을 선택지 수가 다른 질문에서 복사해 오지 않았다

## 운영 ([05](05-operations.md))
- [ ] 비용 추정(N × p95 토큰)과 rate limit 대비 동시성 제한이 있다
- [ ] 응답 `model`, `request_id`, probabilities, 결정 경로를 로그로 남긴다
- [ ] fallback 비율과 점수 분포를 모니터링할 수 있다
- [ ] 버전을 올리는 절차(shadow eval → 재튜닝 → 일부 트래픽 적용)가 정해져 있다
