# 04. 평가와 임계값

> 근거: [reference/08](../reference/08-confidence.md) · [research/domain-practice §6](../research/domain-practice.md#6-임계값-설정-방법론-confidence--noul) · [ecosystem §5 shadow-eval](../research/ecosystem.md#5-설계에-쓸-만한-커뮤니티--3p-실험-결과) · [patterns/catalog 2.1~2.2 self-consistency](../patterns/catalog.md)
> 확인일: 2026-09-24 · 기준: `jev-1.13.0`

**원칙: 평가셋 없이 임계값을 정하지 않는다.** 쿡북과 이 매뉴얼의 숫자는 모두 예시다.

## 1. 평가셋 만들기

| 항목 | 기준 |
| --- | --- |
| 규모 | 결정 하나당 **최소 수백 건**. 3P 권장은 라벨이 있는 결정 1~2k건 |
| 구성 | 운영 분포를 대표하는 표본 + 경계 사례 + adversarial 사례 (사용자 입력이 state에 들어가는 경우) + "해당 없음" 사례 |
| 언어 | **한국어는 별도 슬라이스**로 둔다. 번역 데이터가 아니라 **원문 한국어**로 만든다 |
| 분할 | **튜닝 셋과 테스트 셋을 분리**한다. 튜닝한 셋에서 성능을 보고하지 않는다 |
| 라벨 | 사람이 검수한 골드 라벨. 라벨 기준이 바뀌면(criteria drift) 셋과 문구를 함께 개정한다 |
| 버전 | 셋, 질문 세트, 모델 버전 ID를 함께 기록한다 |

## 2. Shadow eval 절차

운영에 영향을 주지 않고 비교한다.

1. **버전을 고정**한다 (`jev-1.13.0`).
2. 모든 Choice에 `none`/`other`를 넣는다.
3. 기존 경로(현행 LLM, 규칙, 사람)와 **나란히** Jev를 호출하고 결과만 기록한다.
4. 튜닝 셋으로 질문별 보정과 임계값을 정하고, 테스트 셋으로 채점한다.
5. 비교 지표는 **정답 1건당 비용**, 자동 처리 비율(coverage), 자동 처리분의 오류율, p50/p95 지연이다.
6. 한국어 슬라이스를 따로 보고한다.

## 3. 임계값 정하기 (요약)

전체 절차와 참고문헌은 [domain-practice §6.2](../research/domain-practice.md#62-절차-레이블된-평가셋에서-임계값을-고르는-법)에 있다.

1. **점수를 정한다.** Noul은 `noul`, Choice는 `p_top`(또는 위험 선택지의 확률), Score는 기대 점수나 "레벨 ≥ k" 확률의 합. `confidence`는 게이트에 써도 되지만 **보정 해석은 확률에만** 한다.
2. **Reliability diagram**을 그린다 (equal-mass bin 10개 정도). 대각선에서 벗어나면 코드에서 Platt나 temperature로 보정한다 (표본이 적으면 Platt).
3. **Risk-coverage 곡선**: 임계값 t마다 자동 처리 비율과 그 안의 오류율을 계산한다.
4. **목표 오류율 α**를 만족하는 t 중 coverage가 가장 큰 것을 고른다. 이때 **점추정이 아니라 신뢰구간 상한**(Wilson/Clopper-Pearson 95%)을 기준으로 한다.
5. **비용 가중**: 확률이 보정되어 있으면 `t* = C_FP / (C_FP + C_FN)`. 보정이 의심되면 튜닝 셋에서 경험적 비용을 최소화하는 t를 찾는다.
6. **3-way로 변환**한다: `t_high` 이상은 자동, `t_low` 미만은 사람이나 fallback, 그 사이는 확인이나 검토. 되돌릴 수 없는 행동일수록 α를 낮춘다.
7. Choice에서 후보 집합이 필요하면 conformal prediction을 쓴다. 집합 크기가 1이면 자동, 2 이상이면 사람에게 보낸다.

주의:
- **confidence 임계값은 선택지 수에 묶여 있다.** 선택지 수가 바뀌면 다시 튜닝한다 ([reference/08](../reference/08-confidence.md#정의)).
- 확률이 소수 둘째 자리로 양자화되어 있어서 임계값 근처에 값이 몰릴 수 있다. 근처 분포를 확인한다.
- **판정이 결정적이라고 가정하지 않는다.** 반복 호출에서 경계값이 흔들린다는 보고가 있다. 경계값 근처에는 여유 구간(review band)을 둔다.
- 기본값을 그대로 쓰지 않는다. 한 현장 사례에서 기본 임계값 0.85를 쓰자 21건 중 17건이 escalation됐다.

## 4. 회귀 테스트 (CheckList 방식)

모델 출력은 정확한 값이 아니라 **구간이나 순위**로 단언한다.

| 유형 | 예 |
| --- | --- |
| MFT (최소 기능) | 명백한 사례는 기대하는 선택지이고 `p_top ≥ 0.9`여야 한다 |
| INV (불변) | 문장을 바꿔 말하거나, 무관한 문구를 더하거나, 한국어와 영어로 바꿔도 결정이 바뀌지 않는다 (`p_top` 변화가 ±0.1 이내) |
| DIR (방향) | 위험 문구를 추가하면 해당 Noul이 **오른다** |
| 정책 단위 테스트 | 녹화한 응답(고정 JSON)으로 `decide()`의 분기와 임계값 경계를 테스트한다. API는 호출하지 않는다 |

- 평가셋 전체 실행은 CI의 필수 단계가 아니라 **질문, 임계값, 모델 버전을 바꾸는 PR**에서 돌린다.
- 반복성을 측정할 때는 self-consistency 쿡북 방식(같은 입력을 N번 실행해 표준편차를 보는 것)을 쓴다. 반복성은 정확도와 다르다.

## 5. 채택 기준 (케이스 문서에 적는다)

- [ ] 테스트 셋의 자동 처리분 오류율 상한이 목표 α 이하
- [ ] coverage(자동 처리 비율)가 도입 효과를 낼 만큼 충분함
- [ ] 한국어 슬라이스가 따로 기준을 통과함
- [ ] 정답 1건당 비용과 p95 지연이 현행보다 나음 (또는 트레이드오프를 명시함)
- [ ] fallback 경로가 동작함을 확인함
